Pacote de revisão da Máquina do Tempo do Código para rodar a timeline, a FAQ lexical e a página do aluno sem depender da infraestrutura da UFABC. A instância da UFABC atende ao piloto de 2027 e não é um serviço hospedado para outras instituições; cada IES deve implantar a sua própria instância.

Baixar pacote de revisão (.tar.gz) Ver a release Código completo (acesso restrito)

Teste em 5 minutos

Você precisa de Docker e de um navegador atual. O pacote não inclui token, senha nem acesso à rede interna da UFABC.

tar xzf maquina-tempo-review-2026-11-14.tar.gz
cd maquina-tempo-review-2026-11-14
docker compose up --build

# com o serviço no ar, em outro terminal:
./testar.sh

Sem o plugin docker compose:

docker build -t maquina-tempo-review .
docker run --rm -p 8090:8090 maquina-tempo-review

Abra:

http://localhost:8090/tutor/aluno?atividade=cs2-ep04-10-triangulo
http://localhost:8090/tutor/maquina-tempo?atividade=cs2-ep04-10-triangulo
http://localhost:8090/tutor/consentimento
http://localhost:8090/tutor/api/health

O health deve responder ok: true; upstream.ok: false é esperado, porque este pacote não sobe um Ollama.

Portal e turmas de demonstração

O pacote inclui uma conta local de demonstração para testar o portal e o gate de turma:

  • portal: http://localhost:8090/tutor/professor
  • token demo: demo-token
  • EP privado: prof-demo-laco
  • turmas: http://localhost:8090/tutor/professor/turmas

Crie uma turma, gere uma lista/HTML com o EP demo e teste o código. O código aparece uma única vez; rotacione se precisar. A conta demo é apenas local e não existe na instância da UFABC.

Funciona sem GPU

  • execução real de Python no navegador (Pyodide/WASM);
  • linha do tempo, variáveis, saída e fluxograma;
  • casos de teste e FAQ lexical;
  • páginas do aluno, timeline e consentimento.

Precisa de modelo/GPU

  • chat com o tutor socrático;
  • busca semântica com bge-m3;
  • RAG de autoria.

O Ollama roda em CPU com modelos pequenos, mas a latência não atende uma turma de 40 alunos.

Restrições web

  • HTTPS: em produção, sirva a página e o serviço por HTTPS; localhost é a exceção.
  • Mixed content: uma página HTTPS não pode chamar um serviço HTTP.
  • CORS: o serviço precisa permitir a origem do Moodle ou do GitHub Pages em ALLOWED_ORIGINS.
  • CSP: a timeline precisa de wasm-unsafe-eval e do CDN fixo do Pyodide.
  • Iframe: o Moodle precisa permitir o iframe; se ele remover <script>/<iframe>, use o bloco de links.
  • Rede: não exponha o Ollama (11434) nem o proxy (8081); mantenha-os em loopback.
  • Offline: não há modo offline completo; para isso, espelhe o Pyodide e ajuste a CSP.

Privacidade e escopo

O pacote não contém nomes, emails, matrículas, IPs em claro nem token. O chat exige o aceite do termo de consentimento na versão vigente; os logs são pseudônimos. A timeline e a FAQ lexical funcionam sem chat.

Este pacote é público e não tem controle de turma. Em produção, o professor pode distribuir os EPs em HTML, mas a URL do EP, sozinha, não é credencial. O desenho recomendado combina link assinado com expiração, código de turma, cookie HttpOnly e cota por turma. Isso reduz uso casual; para garantir “apenas matriculados”, é preciso LTI/SSO com o Moodle ou código individual por aluno.

O código completo fica no repositório privado fzampirolli/maquina-tempo-cs2. O pacote de revisão é o recorte público para outra IES ou revisor testar localmente. O Artigo 1 descreve a arquitetura, as topologias e as restrições de hardware e web.
